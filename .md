# EA FC 26 Clubs — contexto para otro chat

Documento de handoff. Proyecto: **Chuntaro** (`chuntaro-back` Laravel + `chuntaro-front`). El club del usuario es **Chuntaroo**.

Objetivo actual: usar datos oficiales de EA Clubs (stats, plantilla, partidos, **escudos de rivales**) para gráficos/cartas propias. No usar Pro Clubs Studio como generador; se quiere una solución propia.

## Qué es esta API

La web de EA no es una app aparte: es un front sobre una API **no documentada para partners**, pero pública (la usa ea.com):

```
https://proclubs.ea.com/api/fc
```

No hay auth de “dueño del club”. Cualquiera con el `clubId` ve lo mismo.

**Headers recomendados** (sin ellos, desde servidor a menudo responde `403`):

```
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36
Accept: application/json
Referer: https://www.ea.com/
```

La API puede cambiar o bloquearse. Revisar ToS de EA si se usa en producto.

## Endpoints útiles

Siempre: `platform=common-gen5`.

### Info del club (kits, colores, crest, estadio)

```
GET https://proclubs.ea.com/api/fc/clubs/info?platform=common-gen5&clubIds=2043111
```

También acepta IDs de rivales. Se puede pedir varios separados por coma.

Campos relevantes en `customKit`:

- `crestAssetId`, `crestColor`
- `stadName`
- `kitId`, `customKitId`, `customAwayKitId`, `customThirdKitId`, `customKeeperKitId`
- Colores packed RGB: `kitColor1`–`kitColor4`, `kitAColor1`–`kitAColor4`, `kitThrdColor1`–`kitThrdColor4`

### Stats generales

```
GET https://proclubs.ea.com/api/fc/clubs/overallStats?platform=common-gen5&clubIds=2043111
```

W/D/L, goles, skill rating, rachas, últimos rivales (`lastOpponent0`…), últimos resultados (`lastMatch0`…).

### Historial de partidos (incluye escudo del rival)

```
GET https://proclubs.ea.com/api/fc/clubs/matches?matchType=leagueMatch&platform=common-gen5&clubIds=2043111
```

`matchType`: `leagueMatch` | `playoffMatch` | `friendlyMatch`

Opcional: `maxResultCount` (EA suele devolver ~5 últimos).

Cada partido trae `clubs.{clubId}` con resultado, goles y `details.customKit.crestAssetId` **del rival**. También stats por jugador en `players`.

### Plantilla / Virtual Pros

```
GET https://proclubs.ea.com/api/fc/members/stats?platform=common-gen5&clubId=2043111
GET https://proclubs.ea.com/api/fc/members/career/stats?platform=common-gen5&clubId=2043111
```

Por miembro: gamertag (`name`), nombre del Pro (`proName`), OVR (`proOverall`), posición (`proPos`, `favoritePosition`), goles, asistencias, rating, etc.

**No hay fotos ni renders del Virtual Pro.** Solo números y nombres. Para cartas hay que subir captura del juego.

### Playoffs

```
GET https://proclubs.ea.com/api/fc/club/playoffAchievements?platform=common-gen5&clubId=2043111
```

## Escudos de rivales (lo que se pidió)

La API **no** devuelve una URL de imagen. Devuelve `crestAssetId`. Con eso se arma el PNG.

### Fórmula (FC 26)

```
https://eafc26.content.easports.com/fc/fltOnlineAssets/26E4D4D6-8DBB-4A9A-BD99-9C47D3AA341D/2026/fcweb/crests/256x256/l{crestAssetId}.png
```

La web oficial de EA todavía usa el CDN de FC 24 (mismos archivos):

```
https://eafc24.content.easports.com/fifa/fltOnlineAssets/24B23FDE-7835-41C2-87A2-F453DFDB2E82/2024/fcweb/crests/256x256/l{crestAssetId}.png
```

- Tamaño real: **solo 256×256**. 64 y 128 no existen.
- Es **dinámico para cualquier club de Clubs**: no hay lista hardcodeada. Cualquier rival con `crestAssetId` funciona.
- Si el asset no existe:

```
https://media.contentapi.ea.com/content/dam/eacom/fc/pro-clubs/notfound-crest.png
```

- El GUID del CDN puede cambiar en FC 27. El `crestAssetId` sigue viniendo igual; solo se actualiza el prefijo.
- Son escudos del **catálogo de EA Clubs**, no logos oficiales de equipos reales (salvo que el rival haya elegido ese crest en el juego).

### Dónde leer el ID del rival

Del JSON de `matches`, ignorar `clubId === 2043111`:

```
clubs.{rivalId}.details.customKit.crestAssetId
```

Fallback: `clubs.{rivalId}.TEAM` (suele ser el mismo ID).

Si solo hay `clubId` del rival:

```
GET /clubs/info?platform=common-gen5&clubIds={rivalClubId}
```

### Ejemplo PHP

```php
$MY_CLUB = '2043111';
$CREST_BASE = 'https://eafc26.content.easports.com/fc/fltOnlineAssets/26E4D4D6-8DBB-4A9A-BD99-9C47D3AA341D/2026/fcweb/crests/256x256/l';
$CREST_FALLBACK = 'https://media.contentapi.ea.com/content/dam/eacom/fc/pro-clubs/notfound-crest.png';

foreach ($match['clubs'] as $clubId => $club) {
    if ((string) $clubId === $MY_CLUB) {
        continue; // escudo propio: no pedir, es siempre el mismo
    }

    $id = $club['details']['customKit']['crestAssetId'] ?? $club['TEAM'] ?? null;

    yield [
        'club_id' => $clubId,
        'name' => $club['details']['name'] ?? null,
        'crest_url' => $id ? $CREST_BASE.$id.'.png' : $CREST_FALLBACK,
    ];
}
```

## Investigación previa: Pro Clubs Studio (no usar como fuente)

Se revisó [su API de imágenes](https://platform.proclubsstudio.com/docs/images). Es async (`POST /v1/images` → poll `GET /v1/images/:id`). **No publican modelo ni prompt.**

El producto de consumidores entrena un “player AI model” por jugador (5–10 screenshots, ~10 min). La API partner es más rápida (10–20 s, una sola foto) y luego monta la carta.

Decisión: **hacer la propia**. Pipeline sugerido:

1. Stats/nombres/OVR/posición desde EA.
2. Escudo rival desde `crestAssetId` + CDN (arriba).
3. Foto del Pro: captura subida por el jugador.
4. Retrato con IA (Flux / GPT Image / Gemini) + **composite en código** (Imagick/Sharp) para marco, nombre, OVR, dorsal. No dejar que la IA dibuje el texto de la carta.
5. No clonar el diseño Ultimate Team de EA (IP). Carta con diseño propio de Chuntaro.

## Qué implementar en Chuntaro

1. Client Laravel hacia `proclubs.ea.com` con User-Agent + Referer.
2. Sync: club fijo `2043111`, plantilla, últimos partidos.
3. Para cada partido, extraer rival ≠ 2043111 y guardar `crest_url`.
4. Escudo de Chuntaroo: asset estático `99161115` (o archivo propio).
5. No hay que scrapear ea.com; pegar directo a la API JSON.

No está integrado aún en el repo (ni front ni back tenían estas llamadas al momento de este doc).
